## 🛠️ Learning by Doing

This is the whole course, one more time, at full size. No new instructions to memorize — just the four skills you already have, applied to something you pick.

<CodeLab title="Step 1 — Pick a Real Idea">

Choose something small enough to finish today, but genuinely yours. A few starting points, if you want them:

- A tracker for something you actually do (books read, workouts, habits)
- A tool that solves one small annoyance in your day (a tip splitter, a countdown to an event, a decision-maker for "what should I eat")
- A page that represents something about you (a portfolio, a project showcase, a recipe collection)

Pick the one that makes you want to open it right now.

</CodeLab>

<CodeLab title="Step 2 — Describe, Then Build (Module 1)">

Write your first prompt. Be specific about what it does and how it should feel — the same way you did in Module 1's first build. Run it.

</CodeLab>

<CodeLab title="Step 3 — Loop Through It (Module 2)">

Run at least two real rounds of describe → test → refine. Fix something that bugs you, then add one thing that wasn't there before.

</CodeLab>

<CodeLab title="Step 4 — Expect and Handle a Break (Module 3)">

If something breaks along the way — and with a new idea, something likely will — report it the way you practiced: what you did, what happened, what you expected instead. Don't dread it. You already know this part.

</CodeLab>

<CodeLab title="Step 5 — Run the Stranger Test (Module 4)">

Before you call it done, run the 5-second test, the thumb test, and the silence test on it. Fix the single worst offender.

</CodeLab>

<CodeLab title="Step 6 — Ship It">

Every vibe coding tool has some version of a publish or deploy button — look for language like "Publish," "Deploy," "Share," or "Get a link." Use it.

If your tool doesn't have a one-click option, ask it directly:

> "How do I host this so other people can open it with a link?"

Once you have a link, open it in a new browser tab or on your phone. If it loads there, it's genuinely live — not just visible in your own preview.

</CodeLab>

## 🔍 What You Just Did

You just went from a blank idea to a live, shareable app, using nothing but the same four moves you first practiced on a simple about-me page: describe, refine, debug, evaluate. The idea got bigger. The process didn't change at all.

<Pitfall title="'Finished' Is a Choice, Not a State">

There's always one more thing you could refine. That's true of every piece of software ever shipped, including ones built by large professional teams. Waiting for "no more improvements come to mind" means never shipping.

Pick a reasonable stopping point — the stranger test in Step 5 is a good one — and ship at that point. You can always run another loop later; you can't get feedback from real users on something that's still sitting in a private preview.

</Pitfall>
