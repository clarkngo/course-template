## Account Types

| Type | UID range (typical) | Purpose |
|---|---|---|
| **Superuser (root)** | `0` | Unrestricted access to the entire system |
| **System accounts** | Below 1000 (varies by distro) | Run services/daemons — not meant for interactive login |
| **Regular user accounts** | 1000+ | Human users logging in and doing work |

---

## Where Account Data Lives

| File | Stores |
|---|---|
| `/etc/passwd` | Account metadata: username, UID, GID, home directory, default shell (password field is just a placeholder, `x`) |
| `/etc/shadow` | The actual **hashed password** and password-aging data, readable only by root |
| `/etc/login.defs` | System-wide defaults for newly created accounts (UID ranges, password aging defaults) |
| `/etc/default/useradd` | Another location for `useradd` defaults — view with `useradd -D` |
| `/etc/skel/` | Template files copied into every new user's home directory at creation time |

Modern distributions store the hashed password using **SHA-512** by default (you'll see a `$6$` prefix in `/etc/shadow`) — a major upgrade over the old, now-broken DES and MD5 schemes.

<Pitfall title="Never Edit /etc/passwd or /etc/shadow Directly">

These files can be hand-edited, but a syntax mistake can lock out every user on the system — including root. Always go through the dedicated tools instead:

- `vipw` — safely edit `/etc/passwd` (locks the file, validates syntax on save)
- `vipw -s` — safely edit `/etc/shadow`
- `pwck` — check both files for consistency errors

</Pitfall>

## Creating and Modifying Accounts

| Task | Command |
|---|---|
| Add a new user (with defaults) | `useradd username` |
| Add a user with a full name/comment field | `useradd -c "Jane Doe" username` |
| Add a user whose account expires on a specific date | `useradd -e 2026-12-31 username` |
| Set/change a user's password | `passwd username` |
| Modify an existing user's account expiry | `usermod -e 2026-12-31 username` |
| Attach a real name to an existing account | `usermod -c "Jane Doe" username` |
| Change a user's default shell | `usermod -s /bin/ksh username` |
| Delete a user | `userdel username` |
| Delete a user **and** their home directory | `userdel -r username` |

Populate a new account's home directory from a custom template instead of the default `/etc/skel`:

```bash
useradd -k /path/to/template -m username
```

## Password Aging and Account Locking

| Task | Command |
|---|---|
| View a user's password aging details | `chage -l username` |
| Change how often a password must be changed | `chage -M 90 username` |
| Force a password change at next login | `chage -d 0 username` |
| Lock a user's account (disable password login) | `usermod -L username` or `passwd -l username` |
| Unlock a user's account | `usermod -U username` or `passwd -u username` |

`usermod -L` and `passwd -l` both work by prefixing the hash in `/etc/shadow` with `!`, which makes it impossible to match — this is a *quick* lock, distinct from setting an actual account expiration date.
