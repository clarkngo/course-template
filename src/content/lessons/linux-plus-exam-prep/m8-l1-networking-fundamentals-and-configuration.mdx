## The OSI Model

The **OSI model** is a 7-layer conceptual framework for how network communication happens, from physical signaling up to the application itself. Linux+ questions typically test recognition of the layer, not deep protocol internals:

| Layer | Name | Deals with |
|---|---|---|
| 7 | Application | The protocol the actual software speaks — HTTP, DNS, SSH |
| 6 | Presentation | Data formatting, encryption, compression |
| 5 | Session | Establishing, managing, and tearing down connections |
| 4 | Transport | End-to-end delivery — TCP (reliable) and UDP (fast, no guarantee) |
| 3 | Network | Logical addressing and routing — IP addresses |
| 2 | Data Link | Physical addressing on a local segment — MAC addresses, switches |
| 1 | Physical | The actual bits on the wire, fiber, or radio signal |

The **TCP/IP suite** is the practical, 4-layer model the real internet actually runs on, which maps loosely onto OSI:

| TCP/IP layer | Roughly maps to OSI |
|---|---|
| Application | Layers 5-7 |
| Transport | Layer 4 |
| Internet | Layer 3 |
| Link (Network Access) | Layers 1-2 |

<Pitfall title="Frame vs. Packet: Know the Layer">

A **frame** is the Layer 2 (Data Link) unit of data — it carries MAC addresses and exists only within a single local network segment. A **packet** is the Layer 3 (Network) unit — it carries IP addresses and is what actually gets routed between networks. A router forwards packets between networks; a switch forwards frames within one.

</Pitfall>

## Network Identities and Devices

| Identity | What it is |
|---|---|
| **MAC address** | A hardware-burned, Layer 2 address unique to a network interface |
| **IP address** | A Layer 3, logical address assigned to an interface — can change, unlike a MAC address |
| **Hostname** | A human-readable name for a device on the network |

| Device | Role |
|---|---|
| **Switch** | Forwards frames between devices on the same local network, based on MAC address |
| **Router** | Forwards packets between different networks, based on IP address |
| **NIC** | The physical interface connecting a host to the network |
| **Access point** | Bridges wireless clients onto a wired network |

## DNS and DHCP

**DNS** (Domain Name System) resolves human-readable hostnames into IP addresses. **DHCP** (Dynamic Host Configuration Protocol) automatically assigns an IP address, subnet mask, gateway, and DNS servers to a device joining the network, instead of requiring manual static configuration.

**Common well-known ports** (0-1023 is the reserved "well-known" range):

| Port | Service |
|---|---|
| 22 | SSH |
| 53 | DNS |
| 67/68 | DHCP |
| 80 | HTTP |
| 443 | HTTPS |
| 25 | SMTP (email) |

## Viewing and Configuring Network Settings

| Task | Command |
|---|---|
| View current IP addressing configuration (modern) | `ip addr show` (short: `ip a`) |
| The now-deprecated legacy equivalent | `ifconfig` — replaced by `ip` on virtually every modern distribution |
| View/manage routing table | `ip route` (replaces the legacy `route`) |

<Pitfall title="ifconfig Is Deprecated — Use ip">

The `net-tools` package (`ifconfig`, `route`, `netstat`, `arp`) is no longer installed by default on most modern distributions, replaced by the `iproute2` suite (`ip`, `ss`). The exam expects you to recognize `ip addr`/`ip route` as the current standard, with `ifconfig`/`route` as legacy commands you might still encounter on older systems.

</Pitfall>

**Where network configuration actually lives** (this varies more than almost anything else across distro families):

| File / directory | Purpose | Distro family |
|---|---|---|
| `/etc/sysconfig/network-scripts/` (or NetworkManager profiles) | Per-interface configuration files | RHEL/Rocky/AlmaLinux/Fedora |
| `/etc/netplan/*.yaml` | Declarative network configuration, rendered into NetworkManager or `systemd-networkd` | Ubuntu (modern) |
| `/etc/network/interfaces` | Legacy interface configuration | Debian, older Ubuntu |
| `/etc/sysconfig/network` or `/etc/hostname` | Whether networking is enabled at boot, hostname, default gateway | RHEL-family |
| `/etc/dhcp/dhclient.conf` | DHCP client-side configuration options | Most distros running `dhclient` |
| `/etc/resolv.conf` | Which DNS servers to query (often managed automatically by DHCP or NetworkManager now, rather than hand-edited) |
| `/etc/nsswitch.conf` | Defines the **order** in which name resolution sources are checked (e.g., local `/etc/hosts` file before DNS) via its `hosts:` line |
